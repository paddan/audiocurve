# Rust Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new crate `core/` (`audiocurve-core`) that ports the platform-independent logic of `Packages/AudioCurveCore` from Swift to Rust, with the Swift tests ported as its oracle.

**Architecture:** One standalone crate next to `dsp/`, with a path dependency on `../dsp` (no Cargo workspace, so `dsp/target/…` stays where the Swift build links it). Each Swift source file maps to one Rust module; each Swift test file maps to one Rust integration test file with the same test names in snake case. Swift code and the app build are not touched.

**Tech Stack:** Rust edition 2024; `serde` (derive), `serde_json`, `uuid` (`v4`, `serde`); dev-dependency `tempfile`.

**Spec:** `docs/superpowers/specs/2026-11-18-rust-core-design.md`

## Global Constraints

- The Swift source in `Packages/AudioCurveCore/Sources/AudioCurveCore/<File>.swift` is the reference for every value, constant, rounding and branch. Port it as it is; no behaviour changes.
- Each ported test keeps the Swift test's name in snake case (`prescriptionCasesMatchFixture` → `prescription_cases_match_fixture`) and the Swift test's inputs and expected values.
- Fixtures are read in place with `include_str!("../../Packages/AudioCurveCore/Tests/AudioCurveCoreTests/Fixtures/<file>")`, never copied.
- No platform-specific code, no `#[cfg(target_os)]` except in `store::default_root`. macOS only for building and testing in this step; no Linux/Windows CI.
- Dependencies: `serde`, `serde_json`, `uuid` only (plus `tempfile` for tests). `core` depends on `dsp`; `dsp` never depends on `core`.
- `Swift Double` → `f64`, `Float32` → `f32`, `UUID` → `uuid::Uuid`, `Date` → `std::time::SystemTime` stored as Unix seconds (`f64`), `Int32` pid → `u32`.
- Stored files: `{"version": 1, "value": …}`; readers drop other versions, parse failures and profiles that fail validation. Writes are atomic (temp file in the same directory, then rename).
- Not ported: `OutputDeviceMonitor`, `PluginChannel`, `AppMode`, the layout tests, `ownRouteDevicesAreNotOutputs`, `oldSingleSlotValueIsStillRead`, `snapshotWithoutAttemptsStillDecodes`, `pendingVolumeUsesTheDocumentedKey`, and the old-files half of `measurementRoundTripsAndOldFilesDecode`.
- `cargo clippy --all-targets -- -D warnings` clean at the end of every task.
- Work on a branch `rust-core`, not on `master`.

## Review Focus

1. A profile with a NaN threshold or trim: `validate` must reject it (NaN fails every range check), not accept it and later fail to serialize. Test in Task 1.
2. Non-ASCII profile names (`"Åsa"`, emoji) at the 60-character limit: truncation counts `char`s and never splits one. Test in Task 9.
3. Natural sort: `"Profile 2"` before `"Profile 10"`, `"apple"` before `"Banana"`. Test in Task 9.
4. A store root that does not exist yet, and leftover temp files from an interrupted write: `list` returns what is valid (empty for a missing root), `save_new` creates directories, temp files are never listed. Test in Task 9.
5. Route controller ticked early (`tick(now)` before `next_deadline()`): nothing happens and the deadline stays. Test in Task 10.
